# 🕹️ Мастерская Скинов Minecraft (Crafter Skins)

Профессиональный адаптивный одностраничный сайт (Landing Page) для заказа и скачивания кастомных 2D/3D скинов в кубической стилистике игры **Minecraft**. Проект разработан с использованием современных стандартов фронтенд-разработки.

## 🚀 Демонстрация проекта
*   **Стек технологий:** HTML5, Dart Sass (SCSS), Vanilla JavaScript (ES6+).
*   **Архитектура стилей:** Модульная система 7-1 Pattern, методология БЭМ.
*   **Единицы измерения:** Полностью резиновая верстка на `rem` (доступность и масштабируемость).

---

## 💎 Ключевой функционал

1. **Динамический каталог (52 скина):** Каталог товаров генерируется динамически через JavaScript из массива данных (инкапсуляция базы данных на клиенте).
2. **Живой поиск и фильтрация:** Реализован мгновенный поиск скинов по названию и переключение категорий (Стив, Алекс, HD, 3D) без перезагрузки страницы.
3. **Плавная якорная навигация:** Реализован плавный игровой скролл (`scroll-smooth`) к галерее, интерактивной таблице тарифов и контактам.
4. **Ультра-адаптивная шапка (вплоть до 320px):** На экранах маленьких смартфонов текстовое меню автоматически трансформируется в компактные пиксельные иконки, сохраняя фиксированную высоту хедера (55px) и не перегружая интерфейс.
5. **Безопасный горизонтальный скролл:** Кнопки фильтрации и таблица цен снабжены адаптивными контейнерами `overflow-x: auto`, защищающими интерфейс от горизонтального слома на узких экранах.

## 📂 Архитектура проекта (Модульная структура 7-1)

Проект строго разделен на изолированные модули в соответствии с современными практиками коммерческой разработки:

```text
scss/
├── style.scss          # Главный сборщик, импортирующий модули через @use
├── abstract/
│   ├── _variables.scss # Цветовая палитра Minecraft (Sass Maps) и шрифты
│   └── _mixins.scss    # Миксины для адаптивности (@media) и pixel-art рамок
├── base/
│   └── _reset.scss     # Сброс базовых стилей и настройка множителя font-size (rem)
└── components/
    ├── _header.scss    # Стили компактного адаптивного хедера
    ├── _filter-bar.scss# Стили интерактивного живого поиска
    ├── _skins-grid.scss# Стили резиновой сетки и БЭМ-карточек скинов
    ├── _prices.scss    # Адаптивная таблица тарифов с изумрудной подсветкой цен
    └── _footer.scss    # Игровой подвал с кликабельными контактами (TG, DS, X)
```

## 🛠️ Инструкция по локальному запуску

Для компиляции и автоматического отслеживания изменений в модулях SCSS используется официальный компилятор **Dart Sass**.

1. Установите компилятор глобально в систему (требуется Node.js):
   ```bash
   npm install -g sass
   ```

2. Запустите автоматическую сборку проекта в корень (режим отслеживания):
   ```bash
   sass scss/style.scss style.css --watch
   ```

Мы делаем сайт-каталог скинов и 3D-моделей для Minecraft.Представь, что пользователь заходит на страницу, а там:Сверху — поисковая строка (куда можно ввести, например, «Самурай» или «Робот»).
Чуть ниже — кнопки-переключатели категорий («Все», «Скины Стива», «Скины Алекс», «3D Модели»).Снизу — сетка с карточками товаров. На каждой карточке есть красивая картинка скина, его название, цветная плашка-тег и большая кнопка «Скачать».
При клике на любую кнопку раздается фирменный звук клика из Minecraft.
Что должно работать (наша цель)?Когда пользователь заходит, он видит все 52 скина.Если он нажимает на кнопку «3D Модели», на экране мгновенно остаются только 3D модели, а остальные исчезают.
Если он в этот момент вводит в поиск «Крипер», на экране останется один единственный Крипер-Босс, потому что он и 3D модель, и зовут его Крипер.Мы будем писать код, который управляет этой страницей: фильтрует этот список, ищет нужные слова, включает звуки и генерирует карточки на экране.

База данных (Модель данных): Сначала мы создаем сам список скинов в коде (массив). Чтобы TypeScript нам помогал, мы строго опишем, какие свойства есть у каждого скина (ID, имя, файл и т.д.).

Отрисовка (Интерфейс): Мы пишем код, который берет этот список и просто «выплескивает» его на экран в виде красивых карточек. Теперь пользователь видит все скины.

Состояние (Память сайта): Мы учим сайт запоминать, какую категорию сейчас выбрал пользователь и что он ввел в поиск.

Фильтрация и Поиск (Сама логика): И вот теперь мы пишем ту самую «умную» функцию, которая берет данные из шага 1, смотрит на память из шага 3, отсекает лишнее и обновляет экран из шага 2.

Шаг 3: Состояние приложения (Память сайта)
Теперь нашему сайту нужна память. Давай переведем это на человеческий язык:Когда пользователь ходит по сайту, сайт должен в любую секунду четко знать две вещи:

«Какая категория сейчас выбрана?» (По умолчанию при старте — это строка "Все скины").
«Какой текст сейчас написан в поиске?» (По умолчанию при старте строка пустая — "").
